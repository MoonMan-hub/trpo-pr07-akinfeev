# Ответы на контрольные вопросы

1. **Какие входные данные получает приложение и где они находятся?**
   Адрес и метод HTTP-запроса, а также файлы `data/routes.csv` (маршруты) и `data/pages.json` (данные страниц).

2. **Какой участок кода преобразует данные в интерфейс?**
   Контроллеры готовят массивы и вызывают `View::render()`, а файлы в `views/` выводят их в HTML внутри `layout.php`.

3. **Какое ошибочное состояние проверялось вручную?**
   Неизвестный адрес (404), маршрут `/missing`, отсутствующий и повреждённый `pages.json` (страница 500).

4. **Что изменить при росте проекта?**
   Добавить автозагрузку классов (composer, PSR-4), пространства имён, маршруты с параметрами, модели с данными товаров и базу данных.

5. **Как проверить работу после чистого клонирования?**
   `git clone`, затем `php -S localhost:8000 -t public public/index.php`, затем пройти `docs/checklist.md`.

6. **Какая ответственность у Controller, Model и View?**
   Model читает и хранит данные (`PageModel`). Controller получает запрос от Router, берёт данные у модели и выбирает представление. View только выводит готовые данные в HTML.

7. **Почему Router не должен формировать HTML?**
   Router отвечает только за выбор обработчика по адресу. Если он будет выводить HTML, логику маршрутов и внешний вид нельзя будет менять независимо, а код станет сложным для проверки и повторного использования.

## Показать на защите

**Использование файла из dataset:** `routes.csv` читает `Router::readCsv()`, `pages.json` читает `PageModel`, `shop-logo.svg` показывается в шапке. Удалите строку из `routes.csv`, и этот маршрут перестанет работать (будет 404).

**Путь данных:** адрес `/about` → `index.php` → `Router` находит строку `GET;/about;HomeController;about` → `HomeController::about()` → данные из `PageModel` → `View::render('home/about')` → `layout.php`.

**Ошибочный сценарий:** переименуйте `data/pages.json`, откройте страницу и покажите страницу 500 с понятным текстом вместо fatal error.
